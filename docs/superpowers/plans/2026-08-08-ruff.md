# Migración a ruff — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sustituir flake8 y black por ruff en Neovim, macOS y Linux, dejando de paso verificado el checksum de ruff y arreglado el defecto de arquitectura ARM en `delta` y `dust`.

**Architecture:** Tres capas independientes que se tocan en este orden: la configuración de Neovim (dos strings en `lsp.lua`), la instalación en macOS (una línea del `Brewfile`) y la instalación en Linux (`lib/binaries.sh`, que además necesita un fallback de checksums porque ruff publica un `.sha256` por asset en vez de un archivo consolidado). El arreglo de `delta`/`dust` es un cambio de variable en dos líneas del mismo archivo, en su propio commit.

**Tech Stack:** Lua (conform.nvim, nvim-lint), Homebrew Bundle, Bash 3.2 (macOS) y Bash moderno (Linux), GitHub Releases API.

## Global Constraints

- Spec de referencia: `docs/superpowers/specs/2026-08-08-ruff-design.md`. Todo commit lo cita en el trailer `Spec:`.
- Nunca se commitea a `main`. El trabajo va en la rama `feat/nvim-ruff`, ya creada.
- Mensajes de commit según `.githooks/commit-msg`: `<tipo>(<ámbito>): <asunto>`, asunto en minúscula, imperativo, sin punto final, ≤72 caracteres. Ámbitos válidos usados aquí: `nvim`, `brew`, `lib`, `repo`.
- `shellcheck -x -S warning install.sh` debe pasar. No analizar los `lib/*.sh` sueltos: dan falsos positivos.
- `shellcheck` **no** vale para zsh; aquí no aplica porque no se toca ningún `.zsh`.
- El CHANGELOG se regenera **al final** y va **siempre en su propio commit**, sin mezclar nada más.
- No se añade configuración global de ruff. Ni `config/ruff/ruff.toml` ni symlink en `phase_symlinks`.
- En el guardado entra solo `ruff_format`. No se añaden `ruff_fix` ni `ruff_organize_imports`.

### Task 3: Linux instala ruff con checksum verificado

**Files:**
- Modify: `lib/binaries.sh:42-51` (función `gh_checksums`)
- Modify: `lib/binaries.sh:67` y `lib/binaries.sh:97` (las dos llamadas a `gh_checksums`)
- Modify: `lib/binaries.sh`, bloque *Always* (tras la entrada de `curlie`, línea 132)

**Interfaces:**
- Consumes: `verify_sha256` y `sha256_of` de `lib/common.sh`, sin cambios. `ARCH_TYPE` y `LOCAL_BIN`, globales fijadas por `phase_detect`.
- Produces: `gh_checksums <repo> [asset]` — segundo parámetro **opcional**; con él, si no hay archivo consolidado, busca `<asset>.sha256`. Devuelve el contenido del archivo de sumas por stdout, o código 1 si no encuentra ninguno. Las nueve llamadas existentes siguen siendo válidas sin tocarlas.

- [ ] **Step 1: Comprobar el defecto — ruff no matchea el patrón actual**

Run:
```bash
curl -fsSL "https://api.github.com/repos/astral-sh/ruff/releases/latest" \
  | grep '"browser_download_url"' \
  | grep -iE 'checksums?\.txt|sha256sums?|SHA256SUMS' | head -1
```
Expected: **sin salida**. Confirma que `gh_checksums` devolvería 1 y ruff se instalaría con el warning de "no publica checksums".

- [ ] **Step 2: Añadir el fallback por-asset a `gh_checksums`**

Sustituye la función completa (`lib/binaries.sh:42-51`) por:

```bash
        gh_checksums() {
            local repo=$1 asset=${2:-} response url
            response=$(curl -fsSL "https://api.github.com/repos/${repo}/releases/latest" 2>/dev/null) || return 1
            url=$(printf '%s\n' "$response" \
                | grep '"browser_download_url"' \
                | grep -iE 'checksums?\.txt|sha256sums?|SHA256SUMS' \
                | head -1 | sed 's/.*"browser_download_url": *"//;s/".*//')
            # Algunos proyectos (ruff) no publican un archivo consolidado sino un
            # .sha256 por asset. Sin este fallback caeríamos en el warning de "no
            # publica checksums", que además de falso deja el binario sin verificar.
            if [[ -z "$url" && -n "$asset" ]]; then
                url=$(printf '%s\n' "$response" \
                    | grep '"browser_download_url"' \
                    | grep -F "${asset}.sha256\"" \
                    | head -1 | sed 's/.*"browser_download_url": *"//;s/".*//')
            fi
            [[ -n "$url" ]] || return 1
            curl -fsSL "$url" 2>/dev/null
        }
```

El comentario de cabecera que ya existe encima de la función («No todos lo hacen (delta y dust, por ejemplo…)») se conserva tal cual.

- [ ] **Step 3: Pasar el nombre del asset en las dos llamadas**

En `gh_latest_tar` (línea 67) y en `gh_latest_bin` (línea 97), la línea:

```bash
            if sums=$(gh_checksums "$repo"); then
```

pasa a:

```bash
            if sums=$(gh_checksums "$repo" "$(basename "$file")"); then
```

En ambas funciones `$file` ya está definido en ese punto (`file="$tmp/$(basename "$url")"`).

- [ ] **Step 4: Añadir ruff al bloque *Always***

Justo después de la entrada de `curlie` (línea 132):

```bash

        install_if_missing "ruff" \
            "gh_latest_tar astral-sh/ruff '${ARCH_TYPE}-unknown-linux-gnu.tar.gz\"' $LOCAL_BIN '--strip-components=1 --wildcards */ruff'"
```

Tres detalles que **no** son estilo:
- `ARCH_TYPE`, no `GH_ARCH`: ruff nombra sus assets con el triple de Rust (`aarch64-unknown-linux-gnu`), y `GH_ARCH` traduce eso a `arm64`.
- La comilla de cierre dentro del patrón (`tar.gz\"`) impide que `grep` matchee también `…tar.gz.sha256`.
- `--strip-components=1 --wildcards */ruff` porque el tarball trae directorio contenedor.

- [ ] **Step 5: Verificar el fallback contra el release real**

Run:
```bash
curl -fsSL "https://api.github.com/repos/astral-sh/ruff/releases/latest" \
  | grep '"browser_download_url"' \
  | grep -F 'ruff-x86_64-unknown-linux-gnu.tar.gz.sha256"' \
  | head -1 | sed 's/.*"browser_download_url": *"//;s/".*//'
```
Expected: una URL que termina en `ruff-x86_64-unknown-linux-gnu.tar.gz.sha256`. Es la rama nueva devolviendo lo que el paso 1 no encontraba.

- [ ] **Step 6: Verificar que `verify_sha256` acepta ese formato**

Run:
```bash
cd "$(mktemp -d)"
curl -fsSL -O "https://github.com/astral-sh/ruff/releases/latest/download/ruff-x86_64-unknown-linux-gnu.tar.gz"
SUMS=$(curl -fsSL "https://github.com/astral-sh/ruff/releases/latest/download/ruff-x86_64-unknown-linux-gnu.tar.gz.sha256")
source ~/dotfiles/lib/common.sh
verify_sha256 ruff-x86_64-unknown-linux-gnu.tar.gz "$SUMS" && echo "CHECKSUM OK" || echo "FALLO rc=$?"
```
Expected: `CHECKSUM OK`. Prueba la función real de `lib/common.sh` con los datos reales del release, que es la parte del camino Linux que sí se puede validar desde un Mac.

- [ ] **Step 7: Verificar que el patrón desambigua tarball de sha256**

Run:
```bash
curl -fsSL "https://api.github.com/repos/astral-sh/ruff/releases/latest" \
  | grep "browser_download_url" | grep 'x86_64-unknown-linux-gnu.tar.gz"' | head -1
```
Expected: la URL del `.tar.gz`, **no** la del `.sha256`. Sin la comilla de cierre este mismo grep devolvería ambos y dependeríamos del orden.

Run: `shellcheck -x -S warning install.sh`
